### 手動復帰の方針

手元スイッチだけでは次の問題が残るため、三層で対策する。

| 状況 | 問題 | 対策 |
|---|---|---|
| 使わない日・移動中 | ギアモーターは逆駆動が重く、歯車が噛み合ったままだと手動操舵が重い | 物理離脱レバー（ばねで押し付け、レバーで歯車を外す） |
| 自動操舵中にとっさにハンドルを握る | 解除前にモーターと力比べになる | 電流検知で自動解除。AIO Micro・ファームウェア・AgOpenWebの対応を確認し、未対応なら後付け |
| ソフトが固まる・暴走 | 画面ボタンが効かない | キノコ型非常停止でモーター電源を物理遮断 |

## 2026-11-03 AgOpenWeb調査

調査対象: [AgOpenWeb](https://github.com/AgOpenGPS-Official/AgOpenWeb) `develop` コミット `0790018`（2026-11-02）。READMEと`Docs/`、`Checklists/`、`deploy/android/README.md`、`Shared/`のソースを確認した。

| 確認したこと | 結果 |
|---|---|
| 仕組み | Webサイトではない。誘導計算と制御を行う本体（.NET 10の「ホスト」）を端末上で動かし、画面はそのホストが配信するWebページ。Android版APKは、ホストと画面をスマホ1台で動かすオールインワン構成 |
| 「ブラウザなら何でもよいか」 | 画面だけならLAN上の任意のブラウザ（`http://<ホスト>:5174`）で見られる。ただしホストを動かす機器が1台必要（Android APK、Windows、Linux、macOS）。インターネットはNTRIP補正の受信にだけ使い、操舵はインターネットなしで動く |
| AIOとの通信 | UDPだけ（`192.168.5.x`のサブネット。モジュール宛ては8888番へブロードキャスト、受信は9999番）。シリアルやUSB直結は使わない。端末とAIO Microを同じLANにつなぐ必要がある |
| GNSS入力 | AIOが出す `$PANDA`（シングルアンテナ＋IMU）に対応 |
| NTRIP | クライアントを内蔵。Wi-Fiからテザリングへの切替時の再接続は確認項目に入っている |
| 電流検知の解除 | 設定項目（Current Sensor、しきい値）があり、AgOpenGPSと同じPGN 251でAIOへ送る。解除の判定はAIOのファームウェア側 |
| 成熟度 | ベータ版のみ（`develop`から随時ビルド）。AgOpenGPSと同じ挙動かを確かめるチェックリスト（モジュール通信、操舵設定、Android動作など）は、確認日時点で記入がない |

### 結論

- Android＋AgOpenWebの方針は維持する。ただしベータ版なので、机上試験で次の項目を確かめる。AIO Microとの通信、WASの読み取り、操舵の入切、電流検知による解除、NTRIPの受信、画面を消したときの動作継続。
- うまくいかない場合は、決めてあるとおり中古Windows端末と従来版AgOpenGPSに切り替える。AIOや受信機などの電子部品はどちらの構成でも同じものを使える。
- スマホとAIO Microの接続は、小型のWi-Fiルーター（トラベルルーター）を第一候補にする。ルーターのLAN側を`192.168.5.x`に設定し、有線でAIOにつなぐ。スマホはWi-Fiでルーターにつなぎ、NTRIPはスマホのモバイル回線で受ける。USB-LANアダプターで直結する方法は、Androidで固定IPを設定できるかが機種によって違うため第二候補とする。
