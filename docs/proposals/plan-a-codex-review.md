# プランA：Codexによる技術評価

評価日: 2026-11-03 / 状態: 机上評価・未採用・実機未検証

対象は[新規ISEKI95向けプランA](plan-a-wired-lan.md)。既存の別トラクターを改造する評価ではない。以下はCodexが公式資料を確認して行った評価で、[Claude Codeの回答](plan-a-claude-review.md)とは別である。

## 結論

屋根に測位系、足元に操舵系を分け、キャビン内を整理する目的は妥当。新規にブラシ付きDCギアモーターを選ぶ案も成立候補になる。ただし、IMU完全撤去、薄型アンテナ、BTS7960、小型箱、PoEを一度に確定せず、要求性能と適合するファームウェアから選ぶ。現時点で注文できる確定部品表や実配線図にはしない。

## 優先度の高い確認

### 1. 姿勢と測位品質

UM982は二アンテナ測位・方位に対応し、メーカーの方位仕様は1m基線で0.1°、RTK+Headingは最大20Hz。方位は主アンテナから副アンテナへの基線が基準であり、左右配置では車両前方との変換が必要。仕様値を停車・低速・後退すべての完成機精度と読み替えない。[S1][S2]

幾何学的には、一つの基線から基線方位と仰角を得られるが、基線軸回りの回転は決まらない。横配置の傾斜をロールに利用する場合も、座標・符号・取付姿勢、前後傾斜との関係を確認する。メッセージにheading/pitch/roll欄があることだけで三軸独立観測とは判断しない。この点は基線幾何からの推論で、NovAtelの方位・pitch説明とも整合する。[S2][S3]

デュアル方位は移動軌跡による方位推定と異なり、停車・低速での利点がある。一方、位置RTK Fixと基線方位の品質は別に扱い、RTCM補正の経路・データ時刻・遅延・無効化・再取得を管理する。IMU省略は対応ソフトと地形・動的応答・失陥時挙動を確認してから判断する。IMUがあってもGNSS消失中の自動操舵継続は保証されない。

### 2. 薄型パッチと屋根構造

黒色・薄型という外観は適合根拠にならない。受信機で使うGNSS帯域、能動／受動、LNAバイアス・消費電流・利得、コネクター・同軸損失、メーカー指定グランドプレーン、位相中心・向き、防水・UV・温度・振動を確認する。例えばu-blox ANN-MB2資料はグランドプレーンの変更が位相中心へ影響することを明記している。これは確認観点の例であり、この製品の採用推奨ではない。[S4]

基線は筐体端間ではなくアンテナ位相中心間で管理する。1mバーに50cm同軸という寸法は余長・曲げ・端子位置を含め未確定。屋根材、バーのたわみ、磁石の滑り、二次的な脱落防止、既存ボルト部の荷重・シールを確認する。PETG造形品や受信機単体の環境仕様を完成バーの強度・防水保証にしない。

### 3. 新規DC操舵系と収納

ブラシ付きDCギアモーターを選ぶこと自体を否定しない。先に実操舵負荷、必要回転数・連続トルク、歯車比、起動・拘束電流、使用率、逆駆動・手動離脱性を把握する。BTS7960は半橋ICで、二個型Hブリッジモジュールは別製品。ICの保護・電流値を廉価モジュールの連続定格と同一視せず、基板・端子・配線・冷却・保護とAOGファームウェアの駆動方式を確認する。[S5][S6]

ADS1115はWAS適合を保証する部品ではない。センサーの電源・出力範囲、ADC電源と入力許容、MCU側I2C電圧、断線時検出を確認する。[S7] 箱の寸法は端子・保護・放熱を含めて決める。ハンドル軸、ペダル、膝、可動カバー、整備経路との干渉を避ける。

### 4. 通信・PoE・車載電源

UDPは配送を保証しない。有線でも接触不良・再起動・電源断がある。有効な新しい指令が失われた際のローカルwatchdog、手動解除とMCUに依存しない電源遮断、復旧後の明示的な再エンゲージを設計条件にする。タイムアウト値やピン配線は未確定。[S8]

Teensy4.1はEthernet付き／なし品を区別し、付きでもMagJack等が必要。ESP32は具体的型番とPHY等を確認する。Nano・ESP32・TeensyはファームウェアとI/O・電圧・通信能力が異なり、そのまま交換できない。[S9][S10]

PoEは適合するPSE/PD、受電側変換、電力収支が必要。非PoEハブでは給電できず、単純な12V注入と規格PoEを混同しない。タブレットのLAN一本化は端末電源の一本化とは限らない。スイッチの12V/5V給電も型番の定格次第であり、車載の逆接・過渡電圧・始動低下、ヒューズ・接地・ノイズ対策を確認する。[S10][S11][S12]

### 5. AOGとの接続

AOG公式資料にはDual方位、方位オフセット、RTK喪失停止設定と操舵PGNが存在する。ただし今回の屋根ノードと操舵箱の組合せに対する版別適合は未確認。「NMEAをUDPにすれば動く」とはしない。AOG/AgIOのリリース、基板・MCU、ファームウェアのコミット、UM982ボード／ファームウェア、出力メッセージ・周期・時刻整合を固定して確認する。旧Nano系とAIO Teensy系を混在させない。[S13][S14]

## Claude Code評価との一致・相違

一致点は条件付きでの試作候補、アンテナ適合・基線剛性・失陥時停止・手動解除・車載電源の検証、版を固定した段階評価である。以下はClaude回答をそのまま設計要件にしない点。

| Claudeの表現 | Codexの扱い |
|---|---|
| 「IMU不要で…」への指摘で「ロール補償…は得られません」とし、後段では横基線からロールを得られると記載 | 回答内で表現が一致しない。横基線の傾斜はロール推定に利用できるが、完全三軸姿勢や全地形の補償を保証しない、と整理 |
| IMU省略条件に「平坦」「RTK Fixを常時維持」「20Hz」を挙げる | 提案された限定的な試験条件。メーカー／AOGの普遍的必須条件ではない。品質・更新周期はシステム要求で決定し、欠落は停止条件で扱う |
| 「BTS7960は試作に適します」 | 個別モーター・モジュール・駆動FW・熱・保護の適合は未確認。採用判定にはしない |
| 1mで1mmのずれ、屋根高約3m・ロール5°の例 | 幾何の例示。ISEKI95の測定値ではない。変位方向や補正基準に依存し、機体仕様へ転記しない |
| 拘束試験や実車試験を列挙 | 将来の検証項目。未定格部品を拘束・駆動する指示や実施済み記録ではない |

## 段階案と判断に必要な情報

1. 正式型式・電源・操舵負荷・収納空間・屋根材を確認。安全な負荷評価の方法を別途定める。
2. 従来AIO候補と本案を同じ要求・初回支出・実装負担で比較。全新規調達なので既存部品流用を前提にしない。
3. 操舵を動かさずGNSS・通信を評価。静止・傾斜・低速／後退相当のログ、欠落・再取得を比較し、IMU省略を判断。
4. 具体的部品と版が決まった後に、保護された机上系で停止・手動解除・電源・熱・機械的離脱を検証する計画を作る。
5. 合格条件を満たしたものだけ有人・監視下の段階的車体評価へ進める。現時点で圃場投入可とは判断しない。
